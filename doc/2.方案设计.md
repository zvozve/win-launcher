# WinLauncher 方案设计

> 需求来源：`doc/1.开发需求,md`
> 技术栈：**Qt 6.8.3 + MSVC2022 64bit + Ninja**
> 形态：**弹出式面板**（macOS 26/27 的 Spotlight「应用程序」浮层），不是旧版全屏启动台

---

## 0. 一句话目标

按热键弹出一块圆角毛玻璃面板：顶部搜索栏、下方图标网格；自动读取系统已安装软件；支持拖入 `.lnk` 添加；独立的编辑窗口增删图标与改设置。

## 2. 架构选型（已定）

| 决策 | 结论 | 理由 |
|---|---|---|
| UI 层 | **QML 界面 + C++ 后端** | 毛玻璃/缩放动画/自由拖拽是 QML 舒适区；扫注册表、解析 lnk、激活 UWP 是 Win32/COM 的活 |
| 扫描范围 | **开始菜单 + 注册表 Uninstall** | 只扫开始菜单漏免安装程序；全盘索引噪音太大 |
| 图标 | **`SHGetImageList(SHIL_JUMBO)` 256px → 缓存 PNG** | `QFileIconProvider` 多数只有 32/48，会糊 |
| 毛玻璃 | Win11 `DWMWA_SYSTEMBACKDROP_TYPE = DWMSBT_TRANSIENTWINDOW`；Win10 退回 `SetWindowCompositionAttribute` 丙烯酸 | 兼容性 + 效果双保 |

## 3. 代码结构

```
win-launcher/
├── CMakeLists.txt              Qt6 + AUTOMOC/AUTORCC，单目标 WinLauncher
├── scripts/build.bat           手工拼工具链 → cmake+ninja
├── scripts/run.bat             带上 Qt bin 启动
├── doc/
└── src/
    ├── main.cpp                装配：单实例 / 托盘 / 热键 / 启动顺序
    ├── core/                   不依赖 QML 的后端
    │   ├── appitem.*           条目数据单元（QObject，暴露给 QML）
    │   ├── appscanner.*        buildTasks() 枚举 + runTask() 解析（**都在 GUI 线程**）
    │   ├── shortcutresolver.*  IShellLink 解析 .lnk / .url
    │   ├── iconprovider.*      256px 图标提取 + 缓存 + 归一化
    │   ├── launcher.*          启动：ShellExecute / QProcess / AUMID 激活
    │   ├── windoweffects.*     DWM 材质 / 圆角 / 深色 / 隐藏任务栏图标
    │   ├── launcherwindow.*    QQuickWindow 子类：弹出定位 + Esc/失焦收起 + 热键消息
    │   ├── hotkeymanager.*     RegisterHotKey + 序列解析 + 失败回滚
    │   ├── config.*            config.json / 注册表自启 / 系统深色判定
    │   ├── everythingsearch.*  Everything SDK 动态加载（预留）
    │   └── debugtrace.*        `--trace` 打点写文件（GUI 版看不到控制台）
    ├── app/controller.*        前后端唯一门面，QML 里叫 `Ctrl`
    └── qml/                    全部平铺在模块 WinLauncher 下
        ├── Main.qml            根窗口 = LauncherWindow
        ├── LauncherPanel.qml   搜索栏 + 网格 + 状态行
        ├── EditWindow.qml      独立编辑窗（列表 / 拖放 / 设置）
        └── SearchBar / AppTile / GlassPanel / PillButton / SectionTitle / SettingRow / HotkeyRecorder
```

数据流单向：`AppScanner → Controller → QML`；编辑动作 `QML → Controller → Config/layout.json`。

## 4. 关键技术点

| 主题 | 做法 |
|---|---|
| 弹出定位 | 取 `QCursor::pos()` 所在屏幕，尺寸按屏幕比例算（宽 62% 夹在 760–1280，高 66% 夹在 480–900），居中且上移 1/12 屏高 |
| 窗口 | `FramelessWindowHint \| NoDropShadowWindowHint` + `setColor(transparent)` + `WS_EX_TOOLWINDOW`（不进任务栏）+ 置顶 |
| 收起 | Esc / 失焦（可关）/ 工具栏「关闭」 |
| 全局热键 | `RegisterHotKey` 注册到窗口 HWND，`WM_HOTKEY` 从 `LauncherWindow::nativeEvent` 转给 `HotkeyManager`；改键失败自动回滚 |
| 单实例 | `QLocalServer` 命名管道，二次启动唤起已有实例 |
| 自启 | `HKCU\...\CurrentVersion\Run`，值为 `"exe" --autostart`；启动时读注册表为准 |
| 启动顺序 | **先建引擎/显示窗口，扫描用 `QTimer::singleShot(300ms)` 延后**（原因见 §6） |
| 配置 | `%LOCALAPPDATA%\WinLauncher\config.json` + `layout.json`（手动条目）；图标缓存 `%LOCALAPPDATA%\WinLauncher\cache\icons` |

## 6. 实测踩坑记录（重要，别再踩）

这轮从「一启动就段错误」到跑通，踩了 6 个坑，全部记录在此：

1. **扫描不能放工作线程。**
   `IShellLink::GetIconLocation` 对目标是 shell 命名空间项（UWP / `AppsFolder`）的快捷方式会在 shell32 内部直接段错误（Win11 + SDK 10.0.26100 实测，第一个文件正是 `LiveCaptions.lnk`）。
   → 现状：**不调用 `GetIconLocation`**，图标统一由 `目标文件 → 快捷方式本身` 取。
   → 现状：扫描改回 **GUI 主线程分片执行**（每片 25ms 后 `QTimer::singleShot(0)` 让出），既避开 STA/线程池问题又保持 UI 跟手，顺带能显示「扫描 120/407」进度。

2. **`CoInitializeEx` / `CoUninitialize` 必须配对。**
   线程池线程可能已被别人初始化；`RPC_E_CHANGED_MODE` 时调用 `CoUninitialize` 会破坏进程 COM 状态。只在 `SUCCEEDED(hr)` 时反初始化。

3. **工作线程禁用一切 GUI 侧对象。**
   `QFont` / `QPixmap` / `QFileIconProvider` 依赖 GUI 线程全局状态，在工作线程里用会破坏进程（表现为之后 QML 引擎构造段错误）。`IconProvider` 里用 `onGuiThread()` 显式拦截。

4. **QML 组件文件必须各自 `import` 自定义模块。**
   `LauncherPanel.qml` / `SearchBar.qml` 少了 `import WinLauncher.Core`，结果 `Ctrl` / `AppConfig` 全部静默解析失败：**字面量文本正常显示，所有绑定表达式变成空值** —— 界面看起来「渲染成功但网格空白、底部状态行消失」。
   → 现在装了 `qInstallMessageHandler`，QML 绑定错误会写进 `--trace` 文件。

5. **工具链：`vcvars64.bat` 会调用被安全策略拦截的 `reg.exe`**，导致 Windows SDK 路径没配好（`rc.exe` / `mt.exe` 找不到）。
   → `scripts/build.bat` 改为手工拼 `PATH/INCLUDE/LIB/VCToolsInstallDir/WindowsSdkDir`，不依赖 vcvars。

6. **.bat 必须 CRLF 换行**；且不要用 `if ( ... )` 块包住含 `(x86)` 的路径 —— `%MSVC_ROOT%` 展开出的 `)` 会提前闭合代码块。改用 `if ... goto :label`。
